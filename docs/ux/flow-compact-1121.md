# Compact collection presentation (#1121)

The maintainer approved the compact design and authorized its application to **all Console and Workplace lists**. The earlier Flow-only validation boundary is historical and superseded. Both implementation and stacked coverage remain drafts; neither approval nor merge is authorized.

Resource collections reuse CollectionIdentity and ResourceIcon. Authorized ownership is a discreet 11px I/T/W badge at the icon’s top-left, with an 8px letter and an independent 24px disclosure target. State sits at top-right and the independent managed/inherited lock at bottom-right. Hover, keyboard focus and touch expose the localized complete meaning. Unknown stays neutral. Names come from existing authorized context data, without per-row lookups. A managed resource and an unmanaged resource viewed outside its owner context have distinct accessible lock labels; an unmanaged Instance resource stays unlocked in its own Instance context.

The display name retains its exact permitted destination. Namespace/name is a folder-free second line with complete-value copy immediately after the text. Desktop fine-pointer copy appears on hover/focus; touch copy remains visible. Copy and disclosures are independent from navigation. Family columns, direct primary commands and optional secondary menus remain adapter-owned.

Flows Definitions retains Resource, Version, Updated, Actions. Kind remains discreet resource metadata. The Version column shows the active publication when available, otherwise the latest real immutable publication, or an em dash when unpublished. Draft versions, revision counters and pencils are absent. The prototype-only DraftRevision summary field, client mapping and batch repository lookup have been removed after checking their consumers. Draft authoring, save/publication counters, designer state and run snapshot APIs remain unchanged. Data Source Profiles use the same active/publication fallback. ToolSets resolve the latest real immutable publication for already-visible UIDs in batches of at most 200, returning at most one value per UID; both SQLite and PostgreSQL implement the same query. These family-owned projections include publications without activation. No per-row request or full history load is added. Installed package/extension versions, generation counters, authored archive targets, pinned dependencies and historical versions retain their separate business meanings.

Flows keeps server pagination at 20/50/100 rows. Previous/Next uses nextLink, without an invented total. Size changes reset the page and retain table/card choice. Loading disables controls; failures retain rows and retry the requested page. The visible-page loop still sizes storage batches from discovered rows, so hidden ancestors cannot produce zero-size reads. Both 30-ancestor sparse visibility regressions remain in place, with and without a namespace filter.

The [complete matrix](all-list-adoption-1121.md) and [surface manifest](collection-surfaces-1121.json) cover shared and specialized renderers. Execution scope, audit targets, role assignments, native trees, histories, conversations and selectors retain their real context and interactions. They are reviewed surfaces, not automatic exclusions.
