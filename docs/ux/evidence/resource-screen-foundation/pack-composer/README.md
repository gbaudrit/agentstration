# Pack composition creation

`/pack-projects/new` retains its creation layout and now composes CreationWizard with screen-owned Identity / Resources / Verification fragments. ResourceDefinitionForm owns the single retained EditContext and actual root fields from PackComposerModel, using the existing standard ResourceIdentityFields/Pack naming policy, FormGrid, text/select fields and localized validation. The obsolete four-column metadata layout is replaced by the common two-column grid, with a full-width description and the existing mobile stacking. Free step navigation, explicit incomplete markers and top/bottom navigation remain available before completion. Existing publisher/name/version presence and invalid enum parsing remain enforced; the family API retains coordinate/SemVer and archive/dependency validation. Display-name fallback, authoring version, classification and case-insensitive comma-separated category/manifest-tag cleaning are preserved.

This is Pack **manifest identity**: publisher/name/version are the authored Pack coordinate, while the server assigns the persisted Project's Resource identity. Its manifest Tags are a string list, independently of Resource.Metadata.Tags. No fabricated project technical name, namespace or metadata-label write is introduced. The old scope selector was not sent by CreatePackProjectFromWorkspaceCommand; it is replaced with the actual authenticated request scope, without an additional inventory query or a new ownership parameter. The creation command is unchanged.

The specialized two-sided resource catalogue and live dependency composition remain in Resources, including explicit/automatic inclusions, explanations, pin/demote/remove actions, availability restrictions, external logical bindings and existing catalogue filters. Verification uses a separate read-only summary rather than duplicating interactive preview identifiers. Exact full selected keys are retained independently of subsequent catalogue reads. Stale/cancelled previews cannot replace a later selection; unknown/currently unconfirmed previews have neutral presentation and unknown counters, and cannot enable creation. A failed preview offers a read-only retry; no mutation is retried automatically. The API still recomputes the dependency closure on creation and retains the immutable source snapshot, without copying Secret values or mutating the original resources.

Recoverable catalogue and command errors keep the wizard/model/raw enum state and selection mounted. The shared leave guard preserves pending input; Escape restores the triggering link and explicit confirmation is retained. A successful create clears the guard before opening the actual server UID in the preserved navigation context. Read denial clears private catalogue/draft state. Context replacement cancels previews, resets the old draft and busy state, and ignores a late create acknowledgement instead of navigating into the old context. Commands remain permission-gated, including a forged finish callback. The existing browser page object now visits the actual wizard stages and extracts the returned UID from URL.pathname so a preserved context query cannot corrupt it.

There is an existing contract discrepancy to reconcile separately: ADR-0038 and ResourceScopePolicies describe PackProject/PackProjectBuild as Workspace-only, while PackCompositionService.CreateProjectAsync omits ScopeRef and SqliteResourceStore.ResolveWriteScopeRef selects the current request mode; PutExactAsync does not apply the kind scope policy. This pass reports that code/ADR difference and displays the actual request context. It neither invents a physical Workspace owner for an Instance/Tenant request nor adds a new backend restriction. Browser evidence uses a real Workspace context; administrative-context authoring is not validated as a new supported capability here.

17 focused Pack/composer cases pass, covering retained fields and exact scope/keys, create/refusal, failed-preview retry, recoverable versus denied catalogue reads, independent permissions and a changed context during a genuinely pending create. TypeScript and all three Release hosts pass without warnings/errors. Native English/dark desktop and French/light true-touch probes verify incomplete/free navigation, actual metadata and fixed owner display, invalid classification retained across refresh and steps, full explicit resource selection/review, Escape/focus restoration and real creation preserving the Pack coordinate, authoring version, manifest categories/tags and immutable source references in the actual Workspace. The existing composition/build smoke also passes. The 14 PNGs are unmodified application captures. Exact tested base/source/host hashes and phase results are recorded in verification.json.

New reusable transverse #1236 coverage remains deferred until explicit UX validation and merge. A separate new Pack-creation journey is **Not applicable**: the existing create-pack-project journey is maintained and its composition/build smoke is rerun. The native probes are temporary review evidence, not a prematurely introduced reusable scenario. Full solution suites are omitted at maintainer request; no CI errors are inspected or handled. Shared components and protected Agent source/styles/translations are unchanged in this pass. The existing fixed global mobile navigation/platform overlay remains visible in full-page captures; those real images are unmodified and this pass does not change the global layout.
