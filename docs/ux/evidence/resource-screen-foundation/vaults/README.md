# Vault: validated Console resource foundation

Vault uses the standard Console template and one retained definition form/state/presentation dictionary. Saved Overview places its actual health metric above Identity, with saved labels inside Identity. Definition places Identity before Configuration; the local provider enrichment uses `AdditionalPanels`. Configuration retains the family descendant-use policy, distinct from independent resource Access. The master-key command keeps its own authorization and confirmation. Final YAML exports only the saved resource, read-only.

Creation retains its three-step wizard and family-authorized scope inventory. Namespace is immutable in this family; labels and description are read-only because the existing properties API does not support writing them. No activation capability or new mutation API is invented. The initialization response's command status is not treated as a health status: successful initialization preserves the existing Available presentation.

Refresh retains invalid controls, the same model/EditContext and original ETag; a newer snapshot requires explicit discard. Failed refresh retains content; deletion, loss of access and changed resource coordinates/UID clear private content. Existing commands, ETags and confirmations remain family-owned. Agent product files remain protected.

An initial French touch probe detected horizontal overflow in the initialization key-file path warning. The warning now uses the existing wrapping text style; no path truncation or weaker width assertion is used. This shows the existing local backup path, never key contents.
