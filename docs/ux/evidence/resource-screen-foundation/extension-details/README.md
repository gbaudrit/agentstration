# Extension — saved registration and independent enrollment

An authorized actual registration or enrollment Resource uses ConsoleResourceDetailsTemplate with its saved UID/namespace/owner/governance, metrics before Identity/tags and wrapping Configuration. The registration has one retained ResourceDefinitionForm sharing the exact layout state/presentation dictionary and declared root fields. Standard Identity then Configuration lead to contributions/resources/options/usages/enrollment, independently authorized Access when supported, and final safe read-only YAML. Unsupported description/tag writes remain read-only. An observed inventory-only item without an authorized Core envelope keeps the shared operational Content/Sections frame rather than a fictitious definition or policy.

Saved registration identity remains distinct from observed inventory aliases. Header activation uses its own current ETag and retains unrelated invalid metadata/EditContext; changed reads buffer until explicit discard. Exact scopes/references, confirmations, migration restrictions, direct enrollment commands and independently authorized operations are preserved. Private read loss, replaced UID/context and disposed callbacks clear or reject content. Exported enrollment YAML omits private credential/code-verifier material.

Real native and maintained smoke exposed a context-change callback that completed loading without rendering the result. Its completion now renders under a disposed guard; a deferred-context/deferred-inventory component test covers the actual sequence. Failure to read an associated enrollment is now local common feedback in Enrollment, with explicit retry, while the independently authorized registration stays visible. Direct enrollment read denial still blocks the page and purges private content. Three expected-failure/recovery cases cover forbidden/failed associated reads and denied direct reads; no authorization was broadened.

All 55 targeted Extensions cases pass, including the four new rendering/independent-read cases and four wizard cases. Current TypeScript/catalog checks and warning-free Release hosts pass. Native English/dark desktop and French/light true-touch edit/invalid validation/activation/changed refresh/discard/save and all business sections/YAML pass. Existing local AEP inventory plus governed desktop/mobile journeys pass.

These PNGs are unmodified captures of the running application. Exact source, host, report and screenshot hashes are recorded in verification.json. New reusable #1236 coverage remains deferred until explicit UX validation and merge; maintained journeys continue to be checked. No CI investigation or full solution lanes were performed, as requested.

Observed limits:

- A forbidden associated enrollment is shown as local read feedback rather than being presented as an enrollment success; direct enrollment remains independently authorized.
- Description/tags and YAML writes are unsupported by the current family command API and remain read-only.
- The first native failures were real context-render/independent-read defects. Existing CSS selectors did exist; subsequent semantic selector improvements do not account for or hide these product corrections.
