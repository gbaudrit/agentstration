# Source Provider: validated Console resource foundation

Source Provider uses the standard Console resource template, actual observed-capability metric above saved Identity/labels, one retained common definition form/state/presentation dictionary, Identity before Configuration, the existing observed-capability/usages panels, independently authorized Access and final saved YAML. Extension selection keeps its exact three-part owner/namespace/name key, contribution fallback for a saved/unobserved registration, and original root bindings. No endpoint/credential ownership moves from the extension to the Source Provider.

Creation retains its wizard, authorized extension eligibility, suggestions, automatic technical-name baseline, safe return destination and namespace selection. The common Identity namespace control preserves the existing deferred commit policy. Namespace results are compared using their domain-normalized value. Existing resource links must supply the exact owner: a missing `scopeRef` now shows common failed-load feedback instead of assuming Instance and risking a homonymous resource. Normal generated links already carry namespace/owner/context.

Description and labels stay in Identity read-only because the existing properties API cannot write them. No activation capability or new YAML mutation command is fabricated. Commands, usage-dependent deletion restrictions, confirmations and ETags remain family-owned; Access is independently authorized from the saved UID. Unknown observed state remains neutral.

Refresh retains invalid identity/extension inputs, messages, model/EditContext and original ETag; explicit discard adopts a buffered newer snapshot. Identity replacement/deletion/lost access clears private content. Saved Overview and observed capability use the saved qualified reference, while definition edits remain local.
