# Catalog Tool: validated Console resource foundation

The persisted catalog Tool screen uses ConsoleResourceDetailsTemplate with a real observation metric before saved Identity/labels, standard Definition/Identity then Configuration, the retained execution pane, independently authorized Access and final saved read-only YAML. Its locked ResourceDefinitionForm shares the same section state/presentations; catalog metadata has no unsupported Save. Existing capability, schema-summary/raw-schema, provider and extension provenance panels remain available. This route has no creation flow; the existing Create Tool Definition destination retains exact source/owner/context.

Activation remains an immediate family command with the saved ETag, independent of execution inputs and policies. Definition-write and execution permission checks remain separate: an execute-only reader can run without an activation command, and a writer without execution permission cannot submit a run. Managed/inherited definitions remain locked while independently authorized execution/access retain their own capabilities. Missing discovery does not invent an Unavailable state or a timestamp: the header omits it, uses neutral tone and the saved availability value is an em dash.

Refresh retains visited input editors, invalid raw JSON and results. The execution pane keeps its accepted schema snapshot, so a changed saved contract cannot silently replace pending input. It reports the change, disables submission against the stale contract and supplies an explicit Reset inputs action that adopts the new contract. Reset remounts only the input editor, including its invalid parser buffer, and remains a stable keyboard/touch action. Ordinary metadata/activation refresh preserves the editor. This volatile run input is not presented as an unsaved resource definition and does not create a metadata Save bar. Existing simulation/dryRun locks, real-execution approval rules, error mapping, outputs, diagnostics, receipts and returned-artifact links are preserved.

Resource/provider reads validate exact coordinates; refresh validates UID/address/owner and clears private execution, YAML and policy content on replaced identity/403/404. Recoverable failures retain existing content and drafts. The screen still owns commands, loading, authorization, ETags and family error handling; no generic loading API or second section registry is introduced.
