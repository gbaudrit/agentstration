# Entry — Work definition and six-step creation

The shared standard ResourceDetailsTemplate supplies saved Identity and wrapping Configuration after useful revision/publication/known-usage metrics, standard Definition/Identity and Configuration with family panels, preview/usage/history and final family YAML. Entry is a persisted Work projection without a Core Resource UID, ownership, metadata labels, generic policy or ETag. Its physical execution Workspace remains explicit business context; no Core owner or capabilities are invented. ResourceDefinitionForm retains its exact state and presentation dictionary, root fields and first-error routing/focus.

Creation uses a freely navigable six-step CreationWizard with top/bottom controls and final invalid-field focus. Standard identity and form fields preserve the existing field options/defaults/order/specialized validation, declared Agent/Flow bindings, exposure and conversation behavior. Binary choices use switches; real multi-state policies stay multi-state. A local preview grid min-width/minmax correction fixes actual mobile overflow without hiding content or changing shared/Agent styles. Preview remains non-executing.

The retained EditContext, invalid form and independent raw YAML survive sections and recoverable refresh. Changed snapshots buffer until explicit discard. A successful write acknowledges only its own submitted draft; permission changes preserve a guarded read-only form, while denied reads, foreign context/replaced identity and disposed callbacks clear or reject private state. Actual published history and pinned behavior remain separate from mutable draft revision. Existing API last-write-wins semantics are documented, not replaced by a fake ETag.

The shared frame now omits an owner badge when a projection has no owner and does not fabricate a labels row when labels are absent. Console Core adapters explicitly keep their actual metadata tags; protected Agent remains unchanged. Twenty-one shared tests check owner present/absent and explicit empty labels. All 97 targeted Entry/Tool cases pass after synchronization; TypeScript/catalog checks and warning-free Release hosts pass. Native English/dark desktop and French/light true-touch creation, copy, invalid metadata/YAML, changed refresh/discard, saved binding and mobile bounds pass, together with the three maintained Entry/contract/provenance cases and protected Agent desktop/mobile.

The maintained provenance journey uses an isolated Workspace Bootstrap fixture copied only into its disposable worker catalogue. A real authorized binding lookup, preview, digest and successful application are required before the three original namespaced Entry/Flow/Agent edits. A default-namespace Entry homonym supplies the Pack step because the existing Composer export catalogue supports only default namespace. Exact physical Workspace, namespace and selectable identity are checked through the API and visible card before selection. Installation explicitly chooses the authorized Model/Runtime targets and waits for a new installation success, followed by the original Pack read-only assertion. The official Assistant profile's separate ambiguous Tool ownership is not modified or accepted as a partial success. All existing checkpoint contracts remain unchanged.

The final synchronization preserves fe2eec88's optional MetricCard content and Connected Service diagnostic adjustment. Thirty Connected Service and 21 shared cases pass after synchronization; the three hosts were rebuilt before the final protected Agent desktop/mobile checks. The final Bootstrap run also passes. The Agent test helper verifies immutable technical names exactly and requires a separately editable display name; its product source/styles/translations remain protected.
