# Resource Scope explorer disposition

Route `/settings/resource-scopes` was reviewed individually. It remains outside the top-level resource-list template migration: the primary interaction selects a node in an accessible Instance/Tenant/Workspace ownership tree; the adjacent selected-scope inventory is an embedded detail collection. Converting the entire explorer to a catalog page would remove the relationship between node selection, visibility explanations, current-context guards and resource links. No UI, API, shared component or embedded renderer was changed.

The existing client reads GET `/api/resource-scopes`, authorized with ResourcesRead. ResourceScopeApiService maps ResourceScopeInventoryService, which enumerates only accessible scopes and asks IResourceIdentityCatalog for each exact inventory. The existing identity catalog owns any storage enumeration and contributor aggregation; this review adds no fetch-all client loop. Name/kind/namespace filters operate on the selected node's full returned inventory, reset when that node changes, and do not claim cross-node search or server paging. Links remain gated by the current/ancestor relationship and include namespace/owner/context. Unsupported resource kinds have no invented destination. Current badges, managed markers, counts, selected-node detail and hierarchy stay intact.

The shared-frame and native-tree inventory entries now record this bounded disposition, with source hashes in [source-proof.json](source-proof.json). This is a source/contract review, not new browser adoption evidence. Existing ResourceScopesComponentTests/ResourceScopesLocalizationTests and mapped `resource-scopes.spec.ts`/distribution smoke remain the domain regressions; their full offline lane runs at final handoff. No new test or screenshot is claimed for this documentation-only review. The source-to-inventory assertions cover its unchanged CollectionView and classified native hierarchy. New reusable #1242 is not implemented here.
