## Version and action presentation follow-up

[Earlier version/action captures](evidence/1121/versions-and-actions/README.md) document the previous presentation checkpoint. They are historical; the current compact adoption is verified separately below.

Except for the dedicated Flow Version column, a resource's own applicable version metadata belongs to the identity text column, under its exact qualified name and before governance badges. `CollectionIdentity.Versions` accepts one or more `CollectionVersion` renderers with an explicit localized label. Data Source Profiles show the active publication when available, otherwise the latest actual immutable publication; unpublished profiles show an em dash. ToolSets expose their latest actual immutable publication through a bounded family-specific projection. Agents and Schemas retain the full Generation label because it is a definition-change counter, not a semantic publication version. Extensions (catalog and enrollment), Flows, Packs/projects, ToolSets/assignments and managed extension resources use the same presentation. Referenced dependency versions, runtime software/build inventory and historical version comparisons remain business information with their existing meanings.

`CollectionActions.Primary` accepts multiple directly visible commands. `Secondary` supplies the keyboard-accessible Actions menu; omitting it removes the menu. Existing unnamed child commands remain secondary for compatibility. Family adapters choose the distribution and keep permission guards, disabled states, callbacks and confirmations. Action-menu initialization is idempotent so repeated Blazor renders cannot bind two keyboard handlers and skip the first command. Direct Extension navigation waits for the shared permission context before loading enrollment data and selecting its requested tab; a delayed-permission component regression reproduces the former empty-list race. Model Profile selection exposes Choose directly. Pending extension enrollment commands are primary; paired extension renewal and unenrollment are primary, while credential revocation is secondary. This explicitly refines the earlier blanket menu rule under the maintainer's request; it does not add preference storage or change authorization.

Adapters configure the placement explicitly (button labels below stand for the adapter's existing localized renderers):

```razor
<CollectionActions ResourceName="@displayName">
    <Primary>
        @chooseButton
        @enrollButton
    </Primary>
    <Secondary>
        @inspectLink
        @revokeButton
    </Secondary>
</CollectionActions>
```

Omit `Secondary` when it does not apply. Existing child content without named slots keeps the prior secondary-menu behavior.
