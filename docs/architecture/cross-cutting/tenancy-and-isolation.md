# Multi-tenancy and isolation

Agentstration is not yet a production multi-tenant platform, but its current authorization boundary is shared across resource, Flow, Runtime, Work, Workplace, MCP, and realtime surfaces. The Control Plane has a canonical Tenant and Workspace model plus provider-neutral Principals, local and external identity mappings, Workspace memberships, role assignments, Platform administrators, and enforced ASP.NET Core authorization policies. Local credentials are isolated in the ASP.NET Core Identity store; external authentication uses OIDC/OAuth 2.0. Agentstration does not issue OAuth tokens.

Every owned path carries a canonical instance, Tenant, or Workspace scope through routes, services, repository queries, background processing, and artifacts. Exact-scope operations are distinct from descendant-visible enumeration: instance resources may be visible to Tenant and Workspace descendants, and Tenant resources only to that Tenant's Workspaces. Homonymous resources are not merged or shadowed. Reusable ancestor resources additionally require an explicit local access overlay for descendant discovery or use; visibility or a reference alone does not authorize either action. The overlay is keyed by exact resource identity and changes independently from governed definitions, versions, hashes, and extension provenance. Unauthorized cross-scope reads and mutations do not disclose resource existence.

The selected Console context is one exact administrative scope, not three independent selectors. Instance and Tenant administration use protected operational Workspaces for durable Work, Flow Run, Runtime Run, Trigger, conversation, and artifact state; ordinary Workspace administration uses the selected business Workspace. The operational Workspace is physical placement only. Authorization continues to use the selected logical Instance, Tenant, or Workspace scope, and immutable resource references retain their independent owner scope. The system Tenant is not an ancestor of business Tenants, and operational Workspaces never appear as ordinary business Workspace choices.

The implemented ownership and execution matrix is recorded in the [resource model](../data/resource-model.md) and the [2026-10-26 reconciliation](../implementation/hierarchical-resource-access-reconciliation-2026-10-26.md). See also [ADR-0181](../../decisions/0181-console-context-is-a-single-exact-administrative-scope.md), [ADR-0182](../../decisions/0182-administrative-execution-uses-governed-operational-workspaces.md), and [ADR-0183](../../decisions/0183-triggers-use-operational-workspaces-for-administrative-contexts.md).

A global fallback policy requires authentication except for explicitly anonymous health, bootstrap, authentication, and static-asset paths. HTTP APIs declare contextual resource or Run permissions; MCP tool calls require `runs/execute`; Workplace and Flow Run SignalR hubs require `runs/read`. Platform administration remains global and does not imply a Tenant or Workspace membership.
